Changing a style by hand

Your own table styles · Page 3
Pages 3 to 5 show three ways to change a style: pick one. This page is the first, and it follows 2. Keeping your styles.

This page is a hands-on run-through of changing a style yourself: you save a copy of a built-in style as a style file, change a value or two in RStudio, and check the file before you make a table with it.

A style file is a plain-text file listing every setting a table’s look depends on, one to a line, each after a note saying what it does and what values it takes. Changing a style means changing the value after a setting’s equals sign. On page 4, Changing a style with an AI assistant, an AI assistant makes the changes instead; the copy and the check are the same either way.

This page follows the pattern of every How-To: numbered blocks of code that build one script, with the finished script to download at the bottom. Using the How-To pages explains the pattern, and how to reset your session if something goes wrong.

1. Load jstats and the data

We’ll work on community, one of the two practice datasets that ship with the package: 103 simulated respondents to a community survey. jload() puts a copy of it in your workspace, and juse() makes community the default data frame, so the commands that follow can leave its name out.

## ---- 1. Load jstats and the data --------------------------------------

## Load jstats and the community practice dataset, and make community the
## default data frame. quiet = TRUE skips jload()'s report on what it
## loaded; overwrite = TRUE replaces a copy already loaded in this session
## without asking first
library(jstats)
jload("community", overwrite = TRUE, quiet = TRUE)
juse(community)

The command lines are shown; the standalone ## comment lines aren’t – running a comment just echoes it back and does nothing.

2. A table in the report style

First, make a table to compare the changed one with: descriptive statistics for three variables, saved as d1, in the built-in report style. style = names the style a table is built in.

## ---- 2. A table in the report style -----------------------------------

## Save a result, then make a table from it in the built-in report style
d1 <- jdesc(Age, Income, WellbeingScore, print = FALSE)
t1 <- jtable(d1, style = "report")

3. A copy of report to change

The built-in styles have no file of their own to change. jstyle() with save.as = writes a copy of one as a style file. The copy goes into the style folder, which this block sets, as page 1 did, to a folder named styles inside your project.

## ---- 3. A copy of report to change ------------------------------------

## Keep this page's styles in a styles folder inside the project. jstats
## makes the folder; the setting lasts until R restarts
joptions(style.dir = "styles")

## Save a complete copy of report as mystyle, every setting written out
## with a note. open = TRUE opens the copy in a tab beside your script
jstyle("report", save.as = "mystyle", open = TRUE)

jstats wrote the copy, mystyle.jstyle, into the styles folder, and with open = TRUE the file opens in a tab beside your script. On your screen the copy’s path starts with your own working directory (your project’s folder), which this page shows as ~/your-working-directory. The file is about 800 lines long: every setting jstats has, each after its note. The general settings come first, the ones that set the look of every table, such as the font, the size, and the decimal places. Then each kind of table has a section of its own, under its name in square brackets, such as [descriptives] and [regression], and [plot] comes last, for charts.

NoteReading this output

The first three lines are joptions() confirming the setting it changed. The next two say that jstats created the folder, and where it wrote the file.

4. Change two values, and save

This step happens in the mystyle.jstyle tab, not in the Console. The block below is only comments, a note in your script of what you did.

## ---- 4. Change two values, and save -----------------------------------

## In the mystyle.jstyle tab: font = Times New Roman, decimals = 1, saved

In the mystyle.jstyle tab:

  1. Find the font. Press Ctrl+F (Cmd+F on a Mac), type font = Arial, and press Enter. The first match is the general setting, near the top under “The general settings”. (A second font line, under [plot], sets the charts’ font; leave it as it is.)
  2. Change the value. Replace Arial with Times New Roman, so the line reads font = Times New Roman. Change only what follows the equals sign: the setting’s name stays as it is.
  3. Find the decimals. Search for decimals = 2, and change it to decimals = 1. The note above it says what the setting takes: “a whole number from 0 to 6”.
  4. Save the file, with Ctrl+S (Cmd+S on a Mac). jstats reads the file as it is saved on disk, so a change that isn’t saved doesn’t count.

5. Check the file

jstyle() with a style’s name reads the style file and shows every setting in the Console. If a line holds something jstats can’t use, jstyle() stops at that line and names it, so run it after every change.

## ---- 5. Check the file ------------------------------------------------

## jstyle() reads the saved file and shows every setting. It stops at a
## line it cannot use, and names the line
jstyle("mystyle")

NoteWhy jstats does it this way

A jstats style is a plain-text file, one setting to a line, each with a note on what it does and what it takes. So a style can be read and changed in any text editor, with no special program, and a change is one value on one line. A journal’s style or an agency’s is one small file, which you can email to a colleague or copy to a new computer.

The style is kept apart from the analysis, so one change to the file changes every table made with it: run the script again, and every table is rebuilt in the new look.

TipComing from SPSS, Stata, or SAS?

A jstats style does the job of SPSS’s TableLooks: in the Viewer, a pivot table’s look can be saved as a TableLook file (.stt) and applied to other tables, and a default TableLook set for new output. The difference is where the look is applied. A TableLook styles tables already in the Viewer, and a table exported to Word takes the look it had there; a jstats style is applied as jtable() builds the Word table.

In Stata, collect style commands set the look of a table built with collect, and collect style save keeps them in a file for collect style use; collect export writes the table to Word.

In SAS, the look of ODS output comes from an ODS style, made or changed with PROC TEMPLATE and named in the ODS RTF or ODS WORD statement that writes the file.

NoteGoing deeper (optional)

A general setting can take a value of its own for one kind of table: copy the setting’s line under that table’s heading in the file, and change the value there. decimals = 3 copied under [regression], for instance, gives regression tables three decimal places and leaves every other table as it was. This works for every general setting except paper, which sets the paper size of the whole Word file, and under every heading except [plot], which takes only a chart’s own settings. The help page ?jstyle_settings lists every setting and what it takes. The books cover every setting in depth, and designing a house style, with worked examples.

When jstyle() stops

A slip in the file, such as a misspelled setting or a value the setting doesn’t take, makes jstyle() stop at that line and say what is wrong. Two examples, each made from this page’s file with one line changed:

  • decimal = 1, with the s left off. The message reads line 129 of mystyle.jstyle sets decimal, which is not a setting of a style. Did you mean decimals?
  • decimals = one, a word where a number belongs. The message reads line 129 of mystyle.jstyle sets decimals = one. `decimals` must be a whole number from 0 to 6.

Fix the line the message names, save the file, and run jstyle() again. Your own message gives the line number in your file.

Changing it again

Close the Word file, change the style file, save it, and run blocks 5 and 6 again. jtable() asks before replacing the Word file it wrote earlier: answer y. Block 3 is different: run it again, and jstyle() asks before replacing mystyle.jstyle with a fresh copy of report. Answer n (no) to keep your changes.
