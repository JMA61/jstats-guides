Saving results

Publication tables · Page 1
The pages in this topic are numbered, and each builds on the ones before it, starting with the results you save on this page.

A publication-ready table in Word takes two steps. First, save the result of an analysis under a name. R calls a saved result an object, and this page shows how to make one. Second, give that object to jtable(), which writes the table to a Word file. Page 2, Making a table in Word, shows that step. For many readers those two pages are all they need. Each later page adds one thing: several tables and a chart in one Word file (page 3), several results side by side in one table (page 4), and a choice between the two table looks, called styles, built into jstats (page 5). A second topic, Your own table styles, picks up after page 5, for tables in a look you design or a journal requires.

The Publication tables pages assume you can already run the analyses you’ll put in tables. They don’t cover, for instance, how to choose the predictors for a regression. What these pages cover is the step after the analysis, starting here with saving its result. The page’s last two blocks then save a result in a file, so that a later session can use the result.

This page follows the pattern of every How-To: numbered blocks of code that build one script, with the finished script to download at the bottom. Using the How-To pages explains the pattern, and how to reset your session if something goes wrong.

1. Load jstats and the data

We’ll work on community, one of the two practice datasets that ship with the package: 103 simulated respondents to a community survey. jload() puts a copy of it in your workspace, with the same command that loads a data file of your own. juse() then makes community the default data frame, so the commands that follow can leave its name out.

## ---- 1. Load jstats and the data --------------------------------------

## Load jstats for this session
library(jstats)

## Load the community practice dataset into your workspace, then make it
## the default data frame, so the commands below can leave its name out
jload("community")
juse(community)

The command lines are shown; the standalone ## comment lines aren’t – running a comment just echoes it back and does nothing.

jload() reports what it loaded. The report lists 5 variables with codes, such as -99 and -98, that stand for answers like “Refused” and “Don’t know”; it calls them SPSS-style missing values. jstats sets those codes aside in every analysis, and so in every table: there is nothing to do about them here. The report’s closing lines, about base R and jconvert(), matter only if you also analyze these data with base R’s own functions. The tables on these pages don’t need that, so you can pass over those lines. Declaring missing values explains the codes.

2. Save a result

The first step is saving an analysis result in an object: R’s word for anything it keeps under a name, here the result of an analysis. R keeps an object in its memory for the rest of the session; an object is not a file on your computer. The Environment pane lists the objects you have. You make an object with <-, the assignment operator from Step 3, RStudio Orientation: the name on the left, the analysis on the right. (Step 5, jstats Quick Start, saved a regression this way, under the name Results.)

The name can be almost anything you like. These pages use short ones, d1 for descriptive statistics and m1 for a model, but names like descriptives1 or model_wellbeing work just as well and may be easier to remember. A name can contain letters, numbers, dots, and underscores. It must start with a letter, and it can’t contain a space or a dash, which R reads as a minus sign. Capitalization has to match, as everywhere in R: M1 and m1 are two different names.

## ---- 2. Save a result -------------------------------------------------

## Save jdesc()'s result for three variables in an object named d1.
## The output still appears in the Console, as it would without d1 <-
d1 <- jdesc(Age, Income, WellbeingScore)

3. Save a second result without Console output

The result of any jstats analysis can be saved the same way. Save as many as you like, each in an object of its own. When the Word table is all you want, add print = FALSE inside the command’s parentheses: the result is saved and nothing appears in the Console. (In R, to print a result is to show it in the Console. Nothing goes to a printer or to Word.) Here the second result is a regression of the wellbeing score on age and income, saved as m1.

## ---- 3. Save a second result without Console output -------------------

## Save a regression in an object named m1. print = FALSE keeps the
## output out of the Console, since the Word table is what we're after
m1 <- jlm(WellbeingScore ~ Age + Income, print = FALSE)
Console (lower-left pane) 
ConsoleTerminal×Background Jobs×> m1 <- jlm(WellbeingScore ~ Age + Income, print = FALSE)
> |
Environment (upper-right pane)
EnvironmentHistoryConnectionsTutorial
Data
community103 obs. of 15 variables
d1List of 4
m1List of 20

The Console shows the command and nothing else, and m1 joins d1 in the Environment pane. The regression’s output is saved with the result, though: to see it after all, type m1 in the Console.

4. Save a result in a file

An object is gone when the R session ends. To use a result in a later session, save the result in a file. Give the result to jsave(), the same command that saves a dataset in Loading, Saving, Converting Data. For a result, jsave() needs no file name: it names the file for the object, m1.rds. (The .rds ending marks R’s own file format.)

The block’s second command then removes m1 from the Environment with base R’s rm(). Ending the session would do the same to every object; removing m1 now lets block 5 show the result coming back from the file.

## ---- 4. Save a result in a file ---------------------------------------

## Save the result m1 in a file. jsave() names the file m1.rds
jsave(m1)

## Remove m1 from the Environment, as ending the session would.
## rm() is base R, and shows nothing in the Console when it works
rm(m1)  # base R
Console (lower-left pane) 
ConsoleTerminal×Background Jobs×> jsave(m1)
Saved m1 to ~/your-working-directory/m1.rds
(R format; a jlm() result)
To load it in a later session:
  jload("m1")
> rm(m1)  # base R
> |
Environment (upper-right pane)
EnvironmentHistoryConnectionsTutorial
Data
community103 obs. of 15 variables
d1List of 4

The red arrow points to the broom.

jsave() reports where it saved the file, with the file’s full path, and gives the command that loads the result back in a later session. On your screen the path starts with your working directory (your project’s folder), which this page shows as ~/your-working-directory. If you have set a data folder, as Loading, Saving, Converting Data shows, the file is in the data folder instead.

rm() shows nothing in the Console, and m1 is gone from the Environment pane, which now lists community and d1. The result is still in the file.

rm() removes the one object you name. To remove every object at once, click the broom at the top of the Environment pane, where the red arrow points; RStudio asks you to confirm first.

5. Load the result from the file

In a later session, load jstats, then load the result with jload(), the same command that loads a dataset. Give jload() the result’s name in quotes: it reads the file m1.rds and puts the result in the Environment as m1. The quotes are the one difference from block 4. There, m1 was an object in the Environment; here, "m1" is the name of a file, and in R a file’s name goes in quotes.

## ---- 5. Load the result from the file ---------------------------------

## Load the result saved in m1.rds. It comes back as an object named m1
jload("m1")
Console (lower-left pane) 
ConsoleTerminal×Background Jobs×> jload("m1")

Loaded m1 (R format; a jlm() result made by jstats 0.9.290)
> |
Environment (upper-right pane)
EnvironmentHistoryConnectionsTutorial
Data
community103 obs. of 15 variables

jload() reports where it found the file and what it loaded, and m1 is back in the Environment pane, beside community and d1. The loaded m1 is the result you saved: type m1 in the Console to see the regression’s output, or give m1 to jtable(). The file holds everything a table needs, so in a later session the data do not have to be loaded first. Page 2, Making a table in Word, makes a table from each result.

The file m1.rds stays in your folder until you delete it. The later pages don’t use the file, since each makes d1 and m1 again in its first block. To delete the file, select its checkbox in the Files pane and click Delete.

NoteWhy jstats does it this way

Base R has two commands for this job: saveRDS(m1, "m1.rds") saves the result in a file, and m1 <- readRDS("m1.rds") reads the file in a later session, the name typed twice in each. The file is the same either way: readRDS() reads a file that jsave() wrote, and jload() reads a file that saveRDS() wrote.

The base R commands do less around the file. saveRDS() shows nothing in the Console, so it doesn’t say where the file went. saveRDS() doesn’t use your data folder either: the folder has to be typed into the file name each time, as in "Data/m1.rds". And neither command asks first: saveRDS() replaces a file of the same name, and m1 <- readRDS("m1.rds") replaces an m1 you already have. jsave() and jload() name the file for the object, report the full path, use your data folder when you have set one, and ask before replacing a file or an object.

TipComing from SPSS, Stata, or SAS?

SPSS saves results by saving the Viewer’s output in a file of its own, apart from the data (OUTPUT SAVE). Stata saves a model’s results with estimates save and brings them back in a later session with estimates use. jsave() and jload() do that job here, for the result of any jstats analysis, and a loaded result still makes its table.
