Changing a style with an AI assistant

Your own table styles · Page 4
Pages 3 to 5 show three ways to change a style: pick one. This page stands on its own: it repeats what it needs from the pages before it, so you can start here.

This page is a hands-on run-through of changing how your tables look in Word by asking an AI assistant, such as Microsoft Copilot, ChatGPT, Gemini, or Claude, in plain words: “use Calibri 11 and a dark blue header row”. You make a copy of a jstats style, hand it to the assistant with your request, and check what comes back before you use it. On page 3, Changing a style by hand, you make the same kind of change yourself, in RStudio.

A style is the set of choices that decide how every table looks when jtable() writes it to Word: the font and its size, the shading of the header row, which lines are drawn, how the title and the notes are laid out, how many decimal places a statistic gets, and many more. jstats has two built-in styles. apa follows APA 7 (the American Psychological Association’s style), for journal manuscripts, and is the default. report is the plain look shared by the style manuals that agencies and institutes write for their reports. A copy of either can be saved as a style file, a plain-text file listing every setting with a note on what each does. The copy is what the assistant changes. If you’ve worked through the Publication tables pages and pages 1 to 3 of this topic, the first three blocks will look familiar.

This page follows the pattern of every How-To: numbered blocks of code that build one script, with the finished script to download at the bottom. Using the How-To pages explains the pattern, and how to reset your session if something goes wrong.

1. Load jstats and the data

We’ll work on community, one of the two practice datasets that ship with the package: 103 simulated respondents to a community survey. jload() puts a copy of it in your workspace, and juse() makes community the default data frame, so the commands that follow can leave its name out.

## ---- 1. Load jstats and the data --------------------------------------

## Load jstats and the community practice dataset, and make community the
## default data frame. quiet = TRUE skips jload()'s report on what it
## loaded; overwrite = TRUE replaces a copy already loaded in this session
## without asking first
library(jstats)
jload("community", overwrite = TRUE, quiet = TRUE)
juse(community)

The command lines are shown; the standalone ## comment lines aren’t – running a comment just echoes it back and does nothing.

2. Make a table in the report style

A table starts from a result saved with <-, the assignment operator. Here the result is jdesc()’s descriptive statistics for three variables. print = FALSE keeps jdesc()’s own output out of the Console, since the Word table is what we’re after. (In R, to print a result is to show it in the Console. Nothing goes to a printer or to Word.) jtable() then makes the table in a style, here report, and writes it to a Word file in your output folder. As on Making a table in Word, Publication tables page 2, this assumes you’ve already set your output folder with joptions(output.dir = "Tables"), so the Word file goes in Tables. To set the folder once for every session, put that line in your project’s .Rprofile, as Loading jstats automatically shows.

## ---- 2. Make a table in the report style ------------------------------

## Save a result, then make a table from it in the built-in report style
## and write the table to a Word file. open = TRUE opens the file once it
## is written
d1 <- jdesc(Age, Income, WellbeingScore, print = FALSE)
t1 <- jtable(d1, style = "report", file = "Table1_report.docx", open = TRUE)

## print() is base R: it shows an object in the Console, here the table
print(t1)  # base R

NoteReading this output
  • The first three lines are jtable()’s summary of what it did: the table’s number and title; what the table holds, and the kind of page it goes on in the Word file (portrait here); and where the file was written. jtable() shows this short summary rather than the table itself, so that one call writing several tables doesn’t fill the Console.
  • print(t1) shows the table laid out as the Word table is: the caption (report puts “Table 1:” and the title on one line), the column headings, the rows, and rows of dashes where the Word table has lines. The row labels, such as “Age (years)”, are the variables’ labels from the dataset.
  • What the Console can’t show is the look: a font, a size, a shading color. print() shows the layout, and the Word file is where you judge the look. That matters for this page, because most requests you’ll give an assistant change the look.

3. A folder for your styles, and a copy of report

jstats looks for a style file in a style folder, if you’ve set one, then in your working directory, then in your jstats folder, a folder jstats keeps for you. For this page, the style folder is a folder named Styles inside your project. A style you mean to keep belongs somewhere safer: page 2, Keeping your styles, says where.

jstyle() with save.as = writes a copy of a style into the style folder.

## ---- 3. A folder for your styles, and a copy of report ----------------

## Keep this page's styles in a Styles folder inside the project. jstats
## makes the folder; the setting lasts until R restarts
joptions(style.dir = "Styles")

## Save a complete copy of report as myblue, every setting written out
## with a note. Run this line once: run again, it asks before replacing
## myblue.jstyle, and n (no) keeps the changes your assistant made
jstyle("report", save.as = "myblue", open = TRUE)
Console (lower-left pane) 
ConsoleTerminal×Background Jobs×> joptions(style.dir = "Styles")
Options Settings
Style folder: Styles
Run joptions() to see all settings.

Created 'Styles' folder in working directory.

> jstyle("report", save.as = "myblue", open = TRUE)
Style written to ~/your-working-directory/Styles/myblue.jstyle

> |

jstats made the Styles folder and wrote the copy, myblue.jstyle, into it. With open = TRUE the file opens in a tab beside your script. It is plain text, about 800 lines: every setting jstats has, each after a note saying what it does and what values it takes. Near the top are instructions written for an AI assistant:

# To an AI assistant asked to change this file, from a request in words or to match an example:
# Change only the values after the = signs, using only the values each setting's "# takes:" line allows.
# Where the request is about one kind of table, change that table's section: its own settings, or a general setting's line copied under its heading.
# Keep every other line as it is, and return the whole file, named myblue.jstyle (not .txt).
# Where you cannot make a file, give the whole text for the user to save as myblue.jstyle.
# Then list each value you changed, as it was and as it is now, and each line you added.
# Then say what the request asks for that these settings cannot make, rather than inventing a setting for it.

Those lines name the file to send back, myblue.jstyle: jstats writes the copy’s own name into them. (The name myblue is for the dark blue header row this page asks for.) Give an assistant a complete copy like this one, made by a jstyle() line with save.as = and no settings after it. jstyle() can also write a short file that holds a few settings and takes the rest from the style it is based on, but an assistant given a short file can’t see the settings the file leaves out.

NoteReading this output

The first three lines are joptions() confirming the setting it changed. The next two say that jstats created the folder, and where it wrote the file. On your screen the file’s path starts with your own working directory.

NoteGoing deeper (optional)

Open myblue.jstyle and scroll down. The general settings come first: the font, the size, the caption, the header row, the rules (a table’s horizontal lines), the notes, the decimals. Then each kind of table has a section of its own, under its name in square brackets: [descriptives], [frequencies], [regression], and the rest, with the settings for that kind of table only, such as which columns a regression table shows. [plot] comes last, for charts. The help page ?jstyle_settings lists every setting and what it takes. The books cover every setting in depth, and designing a house style, with worked examples.

4. A copy to upload

An assistant’s upload box takes a file whose name ends in .txt, and some, Microsoft Copilot among them, refuse one ending in .jstyle. So make a copy with the ending .txt for the upload. The copy goes in your working directory, outside the style folder, which should hold only .jstyle files.

## ---- 4. A copy to upload ----------------------------------------------

## file.copy() is base R: it copies a file. overwrite = TRUE replaces an
## older copy, so run this line again before each upload
file.copy("Styles/myblue.jstyle", "myblue.txt", overwrite = TRUE)  # base R
Console (lower-left pane) 
ConsoleTerminal×Background Jobs×> file.copy("Styles/myblue.jstyle", "myblue.txt", overwrite = TRUE)  # base R
[1] TRUE
> |

TRUE means the copy was made. myblue.txt is only for uploading: jstats doesn’t use it as a style. Each time you send the style to the assistant again for more changes, run the line again first, so the upload holds the latest version.

5. Ask your assistant (outside R)

This step happens in your AI assistant, not in R. The block below is only comments, a note in your script of what you did.

## ---- 5. Ask your assistant (outside R) --------------------------------

## Upload myblue.txt with the request on the guide page, and save the file
## that comes back as myblue.jstyle in the Styles folder, replacing the
## copy there

Open a new chat in your assistant, attach myblue.txt, and send this message, with your own request in place of the example in the middle:

Attached is myblue.txt, a jstats table style whose notes say what each
setting does and what it takes. Change it as follows, following the
instructions at the top of the file: use Calibri 11 and a dark blue header
row with white text. Give me the changed file as a download named
myblue.jstyle. Then list each value you changed, old and new, and anything
the settings cannot do.

Then:

  1. Download the file the assistant gives you, and move it into the Styles folder of your project, replacing the myblue.jstyle there. To find the folder outside RStudio, click More (the gear) in the Files tab of the lower-right pane, then Show Folder in New Window.
  2. Check the name in RStudio’s Files tab. Open the Styles folder there: it should hold myblue.jstyle, and no myblue.txt or myblue.jstyle.txt. The Files tab always shows a file’s whole name, while Windows’ File Explorer hides the endings it knows, so myblue.jstyle.txt can look like myblue.jstyle there.
  3. Keep the assistant’s reply. Its list of what changed is what you check the file against in block 6.

Some assistants can’t make a file to download. The instructions at the top of the style file tell an assistant in that case to give the whole text for you to save. Copy that text, open myblue.jstyle in RStudio (click it in the Files tab), select everything in it, paste the assistant’s text over it, and save. The name stays as it was. An assistant that takes no upload at all can be given the text instead: open myblue.txt, copy all of it, and paste it into your message in place of the attachment. The file is long, so check that the reply gives back the whole file.

This route was tested with Microsoft Copilot and with Claude, given the same set of requests: every file that came back read cleanly in jstats, with no setting added, lost, or invented. Other assistants that take a file upload should work the same way, but haven’t been tried yet.

The rest of this page uses a file with the four changes the example asks for, made as the assistants in the test made them: font = Calibri, size = 11, header.fill = 1F3864 (a dark blue), and header.text = FFFFFF (white). Your assistant may choose a different blue.

Now make the same table in the new style. A table keeps the style it was made in, so the new table is made from the result, d1, not from t1.

## second Word file
t2 <- jtable(d1, style = "myblue", file = "Table1_myblue.docx", open = TRUE)

  3 variables, on a portrait page.
Table written to ~/your-working-directory/Tables/Table1_myblue.docx

jtable() wrote the table in myblue to Table1_myblue.docx. Open the two Word files side by side: the second is in Calibri 11, with a dark blue header row and white header text. print(t2) would show nothing new: in the Console the two tables are the same, line for line.

If the assistant’s list names a setting in the [plot] section, look at a chart in the new style as well. jtable() writes a chart from jplot() to Word as a figure, in a style, as it writes a table:

p1 <- jplot(Region)
jtable(p1, style = "myblue", file = "Figure1_myblue.docx", open = TRUE)

Change the look in the style file and run jtable() again, rather than editing the table in Word: the next run writes over any edits made in Word.

NoteWhy jstats does it this way

jstats keeps the look of a table apart from the analysis. The analysis gives the numbers, and the style decides how they are laid out, so one change to the style file changes every table made with it, and running the script again rebuilds every table in the new look. A journal’s style or an agency’s is one small file, which you can email to a colleague or copy to a new computer.

The style file is plain text, one setting to a line, each with a note on what it does and what it takes. That is what lets an AI assistant change one reliably: the notes say what each value means, and jstyle() checks the result.

Base R has no function that writes a table to a Word file. Add-on packages do, each with its own syntax, defaults, and output.

8. If the file comes back as .txt

An assistant told to return myblue.jstyle sometimes returns a .txt file anyway. And on Windows, renaming a file while File Explorer hides its ending can leave it named myblue.jstyle.txt. jstats reads a style only from a file whose name ends in .jstyle. To see what jstats does with a file that ends in .txt, make one on purpose, here named mytest.txt.

## ---- 8. If the file comes back as .txt --------------------------------

file.copy("myblue.txt", "Styles/mytest.txt", overwrite = TRUE)  # base R

## jstats reads a style only from a file ending in .jstyle, so this stops
## (on purpose) and gives the line that renames the file
jstyle("mytest")

What a style can and can’t do

  • One kind of table only. A general setting, such as the decimals or the font, can take a value of its own for one kind of table: the assistant copies the setting’s line under that table’s heading. Ask in words like these: “three decimal places in regression tables only”. This works for every general setting except paper, which sets the paper size of the whole Word file, and under every heading except [plot].
  • Significance stars. Ask for stars and the assistant sets p.format = stars. The table then has no p column, and the stars go on the statistic itself: on b in a regression table, and on t, F, or chi-square.
  • Tables and charts. The [plot] section has a font and a size of its own. Asked for “Calibri 11”, one assistant in the test changed the charts with the tables and another left them alone. Say “for tables and charts”, or “for tables only”.
  • Looks no setting makes. Some looks can’t be made with the settings, such as a bold “Note:” label, or a line under each variable’s rows. The instructions in the file tell the assistant to say so rather than invent a setting, and if one slips in anyway, jstyle() stops at it.

Take the whole script with you

That’s the full run-through. If you’d like the entire script in one file to keep and reuse, download it here. Put your own result in place of d1, and your own style’s name in place of myblue.
